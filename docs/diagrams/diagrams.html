Figure 1 — Deployment topology

Every process that runs in production, the host it runs on, and the protocol between them. The browser never reaches the API directly: all traffic goes through the Next.js server, which holds the session and the upstream address.

Figure 2 — Identity and the request path

How a signed-in person becomes a database identity. The browser holds a cookie, never a token; the API verifies every token cryptographically against the published key set; the database enforces what that identity may see.

Figure 3 — The recording pipeline

From a microphone to a searchable, summarised record. Each step is a queue message, so a failure retries in place and a part that cannot be transcribed leaves a visible gap rather than failing the whole call.

Figure 4 — The permission stack

Four layers, each of which must independently permit an operation. The UI hiding a button is a convenience; the database refusing the row is the rule.

Figure 5 — The assistant, and how a write is approved

The agent answers questions with the caller's own permissions. It cannot change anything by itself: a change is proposed, shown in the conversation that produced it, and applied only when a person confirms.

Figure 6 — Front-end structure and theme

One shell, three surfaces, and a token system that resolves in both themes and both writing directions. Every colour on screen comes from a token; no component holds a literal.

Figure 7 — The data model

The tables a record touches, and what each one is for. Everything is scoped to an organisation; nothing crosses that boundary.
